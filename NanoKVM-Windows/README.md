# NanoKVM for Windows

Experimental, portable Windows client for the same NanoKVM HTTP and WebSocket interfaces used by the Apple app. This is an isolated Tauri 2 project; it does not modify or replace `NanoKVM/NanoKVM.xcodeproj`.

## Goals

- Keep all device, API, authentication and protocol logic in a typed Rust core.
- Keep the web frontend lightweight: navigation, forms and status only.
- Use operating-system TLS: SChannel on Windows, not a bundled third-party crypto engine.
- Never proxy video through HTML video, Canvas, an embedded stock web UI or a guessed codec fallback.
- Decode H.264/H.265 with Windows Media Foundation hardware decode and present through a native Windows surface.
- Store passwords and 2FA-related secrets in Windows Credential Manager, never in web storage or the repository.

## Architecture

```text
NanoKVM-Windows/
  crates/nanokvm-core/    platform-neutral types, protocol, state machines, API client
  src-tauri/              Tauri commands, Windows integration, native video host
  frontend/               small TypeScript UI
```

The Tauri boundary exposes narrow commands and events. The frontend never receives a stored password or a raw authentication cookie. Destructive actions require explicit command-level confirmation semantics and are re-confirmed in the UI.

## Status

The eight pages are wired to typed Rust commands. Device persistence, Windows Credential Manager, mDNS discovery, login and sensitive-action 2FA, supervised video/HID WebSockets, reconnect, keyboard/mouse/touch capture, uploads, EDID generation/rollback, state loading and Windows MFT/D3D11/DXGI hardware-decode submission are implemented. MFT H.264/H.265 output is currently drained without presenting it because the native Direct3D child surface is not yet attached to Tauri. No HTML/canvas fallback pretends that this path is complete. See `docs/PARITY.md` for the exact matrix and validation scope.

## Prerequisites

- Rust stable and Cargo
- Node.js 20+ and npm
- On Windows: Visual Studio 2022 C++ build tools and the Windows 10/11 SDK

No Windows code-signing identity is configured.

## Development

```sh
cd NanoKVM-Windows
npm --prefix frontend install
cargo test --workspace
npm --prefix frontend test
npm --prefix frontend run build
cargo tauri dev
```

## Portable release

The intended portable artifact is the unsigned `.exe` plus only runtime files generated by the Tauri release build. Do not publish or distribute it until the Windows build and realtime path have been validated on Windows hardware.

```powershell
cargo tauri build --bundles none
```

On a non-Windows host, `cargo test --workspace` verifies platform-neutral logic, and `cargo check --workspace --target x86_64-pc-windows-msvc` validates the Windows APIs compile. Hardware decoder activation, latency and the Direct3D presenter require a Windows runner or physical Windows PC and cannot be validated on macOS alone.
